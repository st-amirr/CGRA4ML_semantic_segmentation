Project Overview and Objectives — UPDATED September 7, 2025
==========================================================

1) Primary goal
- Train and deploy a lightweight semantic segmentation model (LMIINet) with Quantization-Aware Training (QAT) for efficient CGRA4ML acceleration on FPGA/ASIC.
- Maintain low parameters/GFLOPs while maximizing mIoU on Cityscapes (512×1024 input).

2) Training code (trainQAT_CGRA4ML.py)
- Model: LMIINet (CGRA4ML-friendly)
   - Encoder/decoder with Lightweight Feature Interaction Bottlenecks (LFIB), channel attention (CC), Channel Reconstruction Unit (CRU), and a compact transformer surrogate (FLAM + CAB + CC) for context.
   - Depthwise+pointwise convs, streamlined skip connections, memory-efficient feature fusion, channel shuffle via slice/concat.
   - Auxiliary supervision: an aux head (softmax) with λ=0.3 combined with the main head.
   - Segmentation head fuses top decoder features and outputs 19 Cityscapes trainIds.
- Quantization (QKeras):
   - 8-bit quantized weights/activations/biases via QConv2D, QDepthwiseConv2D, QBatchNormalization, quantized_relu.
   - Baseline float32 and QAT modes supported; conversion utility folds BN into Conv before transferring to QAT.
- Losses/metrics:
   - Combined loss: main (sparse CE + dice) + λ × aux (sparse CE + dice); ignore index 255 respected.
   - Metrics: pixel accuracy (ignore 255) and mean IoU.
- Data pipeline:
   - Cityscapes loader with robust labelIds→trainIds mapping, ignore=255, albumentations-based augmentations (crop/flip/affine/brightness-contrast/color jitter/HueSatVal/gamma/noise/blur/shadow/rain, etc.).
   - Generator yields full-res mask for main and 1/16-res for aux automatically.
- Training control & callbacks:
   - Polynomial LR decay scheduler; per-epoch weight checkpoints (weights-only); TensorBoard; validation visualizations with Cityscapes palette.
   - Optional BN freeze cycle and decoder freeze cycle to stabilize QAT.
   - Final inference model exported without auxiliary output and with training-time dropout disabled.
- TF runtime:
   - Safe threading, GPU memory growth, optional XLA JIT, CPU prediction in visualization callback to avoid XLA compile overhead.
- CLI flags:
   - --trainQAT, --epochs, --batch_size, --use_dropout, --subset_ratio, --LR, --load_model, --freeze_dec, --use_autokeras (reserved), --freeze_bn, --aug.

3) CGRA4ML build (build_cgra4ml_model.py)
- Purpose:
   - Load trained Keras/QKeras .h5 models, analyze topology/skip connections, create a minimal CGRA4ML config, export hardware configs/TCL, and optionally synthesize/simulate.
- Flow:
   1. Load QAT model with custom_objects (QKeras layers).
   2. Verify shapes (expected 512×1024×3 → 512×1024×19) and analyze skip connections.
   3. Create CGRA4ML config (clock, PE rows/cols, data width, skip strategy).
   4. Convert/export: instantiate Hardware, export config_hw.svh and Vivado TCL, export inference vectors. Optional verification.
   5. Predict performance using DeepSoCFlow (fallback rough estimate if unavailable).
   6. Generate performance report JSON and deployment guide.
   7. Update deepsocflow/rtl/defines.svh and tcl/fpga/zcu104.tcl to reference the latest model build directory and config_hw.svh path.
   8. Optional: synthesis (Vivado) and simulation (verilator/xsim); update report with sim results.
- Defaults:
   - Part: xczu7ev-ffvc1156-2-e (ZCU104), freq 200 MHz, PE grid 16×64, bits_input/weights=8; Windows-friendly (no bash requirement).
- Key artifacts:
   - cgra4ml_models/lmiinet_cgra4ml_<timestamp>/ with config files, TCL, performance report (cgra4ml_performance_report.json), and a deployment guide.

4) Datasets & environment
- Cityscapes (19-class trainIds) with ignore label 255; docker-compose based training/evaluation; TensorBoard logs under /workspace/models/tb_logs.

5) Current status (code capabilities)
- Baseline and QAT training paths supported with resume-from-checkpoint.
- Visualization and metrics integrated; auxiliary supervision wired into training.
- Build pipeline converts trained .h5 models into a CGRA4ML project with optional synth/sim and performance reporting.

6) Next steps
- Run float32 pretraining then QAT fine-tuning with BN/decoder freeze where helpful.
- Validate mIoU and resource/throughput on ZCU104 via build pipeline; iterate PE grid/frequency if needed.
- Optionally experiment with head variants (e.g., Lite-ASPP-style) within CGRA4ML op set, keeping params/GFLOPs budget.
