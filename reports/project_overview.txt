Project Overview and Objectives
==============================

1. **Primary Goal:**
   - Train a semantic segmentation model for FPGA implementation using hls4ml and QKeras with Quantization-Aware Training (QAT).
   - Maximize segmentation accuracy while ensuring the model fits and runs efficiently on high-end FPGAs (e.g., Xilinx VCU118).

2. **Technical Context:**
   - **Training Strategy:** Two-phase approach following hls4ml best practices:
     * Phase 1: Float32 baseline training for optimal convergence (50-100 epochs)
     * Phase 2: QAT fine-tuning using trained float32 weights (15-30 epochs)
   - **Frameworks:** TensorFlow/Keras for model definition and training; QKeras for quantization; hls4ml for FPGA conversion.
   - **Quantization:** Multi-precision quantization strategy:
     * 8-bit: Input/output and light encoding layers (encoder1, decoder0)
     * 16-bit: Medium complexity layers (encoder2, encoder3, decoder1, decoder2)
     * 32-bit: Critical layers requiring high precision (bridge, decoder3)
   - **Model Architecture:**
     - U-Net encoder-decoder with skip connections, attention blocks, and multi-precision quantization
     - FPGA-compatible design (no MaxPooling2D, optimized for hls4ml synthesis)
     - Input size: 512x1024x3, output: 512x1024x34 (Cityscapes dataset, 34 classes)
     - Configurable dropout layers (automatically removed for HLS4ML export)
   - **Data Pipeline:**
     - Efficient `CityscapesDataGenerator` with Albumentations augmentation
     - Configurable dataset subset ratios for testing (0.1-1.0)
     - Optimized batch processing with prefetch buffer
   - **Training Environment:**
     - Docker container with GPU support and comprehensive dependency management
     - GPU utilization optimizations (XLA JIT, memory growth, non-deterministic ops)
     - TensorBoard integration for real-time monitoring with comprehensive metrics
   - **Monitoring & Visualization:**
     - Real-time TensorBoard logging with organized metric groups
     - Custom prediction visualizations with Cityscapes color coding
     - Learning rate tracking and IoU metrics per class
     - Automatic checkpoint resumption and progress persistence

3. **Key Technical Features:**
   - **Automatic Weight Transfer:** Seamless conversion from float32 to QAT models
   - **Smart Training Resume:** Automatic detection and resumption from latest checkpoints
   - **Comprehensive Monitoring:** TensorBoard scalars, images, and custom visualizations
   - **HLS4ML Export Ready:** Clean models automatically generated without dropout layers
   - **Resource Optimization:** Configurable batch sizes, subset ratios, and worker processes

4. **Performance Expectations:**
   - **Phase 1 (Float32):** Expected IoU 0.35-0.55 (significant improvement from previous 0.12-0.14)
   - **Phase 2 (QAT):** Expected IoU 0.30-0.50 (maintains good performance after quantization)
   - **Training Time:** ~6-8 hours Phase 1 + 2-3 hours Phase 2 = ~9-11 hours total

5. **Common Issues and Solutions:**
   - **Previous QAT Issues:** Resolved by implementing two-phase training approach
   - **GPU Utilization:** Optimized through XLA JIT, proper memory management, and float32 computation
   - **Monitoring:** Comprehensive TensorBoard integration with persistent data storage
   - **Model Export:** Automatic generation of clean HLS4ML-compatible models

6. **Dataset & Environment:**
   - Cityscapes dataset with standard directory structure (34 classes)
   - Docker-based training with volume mounting for data persistence
   - TensorBoard accessible at localhost:6006 for real-time monitoring

7. **FPGA Deployment Pipeline:**
   - Trained models automatically export HLS4ML-compatible quantized weights
   - Clean model architecture without training-specific layers (dropout)
   - Multi-precision quantization optimized for FPGA resource utilization
   - Target: Xilinx VCU118 or similar high-end FPGA platforms
   - Quantization and architecture choices are made with FPGA resource constraints in mind.
