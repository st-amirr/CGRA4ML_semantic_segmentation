HLS4ML QAT Toggle Implementation Report
=========================================

Date: August 2, 2025
Project: Semantic Segmentation for FPGA Implementation using hls4ml

Executive Summary
-----------------
This report documents the implementation of a new two-phase training approach for HLS4ML semantic segmentation models. The previous approach of training directly with Quantization-Aware Training (QAT) resulted in poor convergence with IoU plateauing at ~0.12-0.14. The new implementation follows hls4ml best practices by training a float32 baseline first, then applying QAT as a fine-tuning step.

Problem Analysis
----------------
1. **Previous Training Issues:**
   - IoU stuck at 0.12-0.14 after 52 epochs
   - Direct QAT training from scratch
   - Poor convergence due to quantization constraints during initial learning
   - Model struggling with aggressive quantization from epoch 1

2. **Root Cause:**
   - Training with quantized layers from the beginning limits model's ability to learn complex features
   - Quantization noise interferes with initial weight learning
   - QKeras layers have different optimization dynamics than standard layers

Solution Implementation
-----------------------

### New Two-Phase Training Approach

**Phase 1: Float32 Baseline Training**
- Train model without any quantization constraints
- Allow full precision learning for optimal feature extraction
- Expected IoU improvement: 0.35-0.55 (vs previous 0.12-0.14)
- Learning rate: 1e-3 (standard)

**Phase 2: QAT Fine-tuning**
- Load trained float32 model
- Convert to QAT architecture with automatic weight transfer
- Fine-tune with quantized layers
- Learning rate: 1e-5 (lower for stability)
- Expected final IoU: 0.30-0.50 (small drop from float32 but much better than previous)

Technical Architecture
----------------------

### Model Architecture Compatibility:
- Same U-Net inspired encoder-decoder structure
- FPGA-compatible layers (no MaxPooling2D)
- Strided convolutions for downsampling
- Channel attention mechanisms
- Skip connections preserved

### Quantization Strategy:
- 8-bit quantization for weights and activations
- Symmetric quantization with auto_po2 alpha
- Stochastic rounding enabled
- Same quantization parameters as original but applied post-training

### Data Pipeline:
- Unchanged from original implementation
- CityscapesDataGenerator with on-the-fly loading
- Albumentations for data augmentation
- Memory-efficient batch processing

Usage Instructions
------------------

### Quick Start:
```bash
# Start Docker container
docker-compose up -d
docker-compose exec hls4ml-training /bin/bash

# Phase 1: Train float32 baseline
python train_qat_toggle.py --trainQAT=False --epochs=50 --batch_size=2

# Phase 2: Apply QAT (after Phase 1 completes)
python train_qat_toggle.py --trainQAT=True --load_model=/app/models/float32_best.keras --epochs=20 --batch_size=2

# Compare models and prepare for hls4ml
python compare_models.py --float32_model=/app/models/float32_best.keras --qat_model=/app/models/qat_best.keras
```

Conclusion
----------

The new two-phase training approach addresses the fundamental issue of poor convergence in direct QAT training. By separating float32 baseline training from quantization-aware fine-tuning, we expect significant improvements in model performance while maintaining compatibility with hls4ml and FPGA deployment requirements.

**Key Success Metrics:**
- IoU improvement from ~0.12-0.14 to expected ~0.30-0.50
- Successful FPGA synthesis with quantized weights
- Maintained training efficiency and resource requirements
- Improved developer experience with clear workflow separation

The implementation provides a robust foundation for high-quality semantic segmentation models suitable for FPGA deployment while following established best practices in quantization-aware training.
